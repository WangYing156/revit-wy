# 踩坑与排错

> 本文记录的是**已经在本仓库代码里处理掉**的问题，以及处理方式。
> 遇到问题时先查这里，再查 `%APPDATA%\revit-wy\plugin.log`。

---

## 一、部署类

### 1.1 Revit 里看不到 revit-wy 功能区

| 检查 | 命令/位置 |
|---|---|
| .addin 文件在不在 | `%APPDATA%\Autodesk\Revit\Addins\2022\RevitWy.Plugin.addin` |
| DLL 路径对不对 | .addin 里 `<Assembly>revit-wy\RevitWy.Plugin.dll</Assembly>` 是相对 .addin 所在目录 |
| Newtonsoft.Json.dll 拷了没 | 要和主 DLL 同目录 |
| DLL 被"锁定" | 从网上下载的 ZIP 解压出来的 DLL 会被 Windows 标记。右键 → 属性 → 解除锁定；或 `Unblock-File *.dll` |
| .NET Framework 4.8 | Windows 10 1809+ 自带；更老的系统要装 |

> **本项目已修**：Ribbon 按钮的类名必须是 `RevitWy.Plugin.Commands.CmdInfo`（带命名空间），
> 早期写成 `RevitWy.Plugin.CmdInfo` 会导致点按钮报 "找不到类"。

### 1.2 编译报 `Could not load file or assembly 'RevitAPI'`

原因：`<Private>True</Private>` 把 RevitAPI.dll 复制到了输出目录，运行时加载到两份。

修：所有 Revit API 引用加 `<Private>False</Private>`。

### 1.3 编译报 Newtonsoft.Json 版本冲突

Revit 2022 自带 Newtonsoft.Json **13.0.3**。项目里必须锁同一个版本，否则绑定重定向会炸。

### 1.4 `UnitType.UT_Length` 编译警告/错误

Revit 2022 起 `UnitType` 和 `DisplayUnitType` 已废弃。改用：

```csharp
units.SetFormatOptions(SpecTypeId.Length,
    new FormatOptions(UnitTypeId.Millimeters, 0.1));
```

> **本项目已修**：`CommandDispatcher.PrepareProject`。

## 二、连接类

### 2.1 `doctor` 显示 connected=false，错误是 Connection refused

可能原因（按概率）：

1. Revit 没打开（或有项目文档没开）
2. 插件没加载 → 看功能区有没有 revit-wy
3. 端口不一致 → `addin/RevitWy.Plugin/config.json` 与 Python 侧 `--port` 对比
4. 端口被占用 → 点功能区「重启服务」，看是否报占用

### 2.2 首次请求卡住 10 分钟然后超时

原因：Revit 弹出了模态对话框（比如"是否保存"、"族未激活"），挡住了 `ExternalEvent` 的执行。

处理：看 Revit 窗口有没有对话框，关掉后重试。日志里会有对应 timeaout 记录。

> **本项目已处理**：`ExternalEventBridge.Invoke` 带超时，不会无限等待；错误码 `TIMEOUT`
> 并提示"可能弹出了模态对话框"。

### 2.3 WorkBuddy 里工具列表是空的

99% 是 **没点 Trust**。桌面版 → Experts · Skills · Connectors → Connectors →
MCP Server Management → 找到 revit-wy → Trust。

### 2.4 WorkBuddy 改了配置没生效

你改的可能是 `~/.workbuddy/.mcp.json`（带点，自动生成，会被覆盖）。
要改 **`~/.workbuddy/mcp.json`**（不带点）。

### 2.5 Cursor 里 `python: command not found`

Cursor 不继承 PowerShell 的 PATH。`command` 写绝对路径：

```json
"command": "D:\\revit-wy\\.venv\\Scripts\\python.exe"
```

## 三、图纸处理类

### 3.1 `ezdxf` 报不能读 DWG

设计如此。DWG 是闭源格式，ezdxf 只支持 DXF。

```powershell
revit-wy dwg2dxf D:\drawings --workers 4     # accoreconsole，需装 AutoCAD
revit-wy dwg2dxf D:\drawings --oda           # ODA File Converter 兜底
```

### 3.2 图幅显示 5000m × 3000m

图纸单位标错（实际画的是 mm，头里写了 m；或反之）。

处理：在 `config/bim_rules/default.yaml` 里设 `units.conversion: force_mm`，
或用 `--units` 参数。扫描报告里 `warning` 字段会提示图幅 >200m 的情况。

### 3.3 墙识别出的厚度是 800 或 1200

双线配对配错了：把外墙两侧的**不同两面墙**配成了一面。

调 `pair.max_thickness_mm`（默认 500 → 改 300），或提高 `overlap_min_ratio`。

### 3.4 墙数量只有实际的一半

图纸上墙是单线画法（或双线间距超出 60–500mm 范围）。

排查：
1. 看干跑的 `walls_from_pairing` 占比
2. 若 `unpaired_lines` 很高 → 墙是单线 → 靠 `thickness_suffix` 从图层名取厚度
3. 确认图层名是否带厚度（`A-WALL-200`）。没带的话，把后缀规则加到映射 yaml

### 3.5 门窗全丢

原因排序：
1. 门窗不在 `door`/`window` 类图层 → 确认单里把它们指到 `door` 或 `window`
2. 门窗是普通 LINE 不是 INSERT → 一期不支持（需要二次开发块识别）
3. 门窗图层被误判成 `isolate` → 确认单里改回来

### 3.6 门窗尺寸都是 900×2100

块没有属性（`宽度`/`WIDTH` 等 tag），走了默认值。这是设计行为——但报告里应能看出。
如果需要精确尺寸，建议上游在门窗块里加属性，或用块的几何包围盒推算（二期）。

### 3.7 轴网名字是 KZ1、KL2

已修的 bug：轴号防误判黑名单（`MEMBER_LABEL` 正则）现在会排除构件编号。
如果你的图纸轴号也是 `K1` 这种，会和白名单冲突，需要调 `GRID_LABEL_OK`。

> **本项目已修**：`geometry._is_grid_label`。

## 四、Revit 建模类

### 4.1 报"找不到宿主墙，已跳过"

含义：门窗中心点到所有墙中心线的距离都超过容差。

真因通常是：
- 墙没识别出来（先看墙数对不对）
- 图纸上门窗和墙不在同一位置（比如门窗画在墙的中心线上，而墙中心线提取偏了）

处理：加大 `OpeningBuilder.FindHost` 的容差（默认 150mm / 400mm），或先修墙的问题。

> **设计决定**：宁可跳过并报错，也不硬插悬空构件。悬空构件清理比不建麻烦得多。

### 4.2 报"项目内无结构柱族"

样板里没有柱族。载入：插入 → 载入族 → 结构 → 柱 → 混凝土 → 混凝土矩形柱。

或者用 `list_types` 协议方法先看看项目里有什么。

### 4.3 墙建出来了但颜色/类型不对

类型匹配走了"厚度相近"分支。在 Revit 里看类型名是不是 `常规 - 200mm` 之类。
可以先用 `list_types {"category":"wall"}` 看项目现有墙类型，再调 `type_name_template` 让规则名字对上。

### 4.4 模型里同一面墙有三个

改图后没清理就重跑了。

正确流程：
1. Revit 点「清理上次翻模」（只删带 `revit-wy` 标记的）
2. 重跑 `build --send`

### 4.5 大模型（>5000 构件）Revit 假死

单事务提交 5000 个构件，Revit 会长时间无响应。

处理：按楼层/区域分批；或改用 `per_element` 模式：

```python
rwy_build 传 transaction_mode="per_element"
```

### 4.6 报 `The transaction has already been rolled back`

已修：所有 Commit/RollBack 前改用 `tx.GetStatus() == TransactionStatus.Started` 判断。
builder 内部出错时会自行回滚，外层不能重复操作。

> **本项目已修**：`CommandDispatcher.InTransaction` + `ModelBuilder` 各处。

### 4.7 干跑阶段报错说缺类型

已修：干跑（`dry_run`）原本会调 `ResolveWallType`，而该方法在类型不存在时会**复制**一个新类型——这是写操作，干跑不该发生。现在干跑只做存在性检查并列出"将需要哪些墙厚类型"。

> **本项目已修**：`ModelBuilder.Validate`。

## 五、其他已修复的问题（供参考，避免重犯）

| # | 问题 | 原因 | 修法 |
|---|---|---|---|
| 1 | Ribbon 按钮点了没反应 | 类名少了 `.Commands` 命名空间 | `Assembly.GetExecutingAssembly().Location` + 完整类名 |
| 2 | Bridge 挂载 UIApplication 永远失败 | `UIControlledApplication.Idling` 的 sender **不是** UIApplication | 删掉该逻辑，改为 `ExternalEvent.Execute(app)` 里拿 |
| 3 | `extract_grids` 报 `'Primitive' object is not subscriptable` | 传参时把 `(text, point)` 元组构造错了 | 先构造 `grid_texts = [(p.text, p.points[0])]` |
| 4 | IR 里墙的标高名 `标高 1` 在项目里不存在 | CLI 默认值与标高生成名 `1层` 不一致 | `build()` 内做名称归一化，不存在则回落到首层 |
| 5 | MCP 服务启动即崩 | `mcp` 2.x 把 `FastMCP` 改名 `MCPServer` | 三级 import 兼容（2.x / 1.x / fastmcp） |
| 6 | 门窗成功数统计串了 | 门和窗共用同一个 `Failed` 计数 | 分开统计 `CreatedDoors` / `CreatedWindows` |
| 7 | 轴号被识别成构件编号 | 轴号取"最近文字"没有过滤 | 加白名单 + 构件编号黑名单 |

### 错误码对照

| 错误码 | 含义 | 首要排查 |
|---|---|---|
| `NO_DOCUMENT` | Revit 没打开项目 | 打开 .rvt 而不是停在起始页 |
| `BAD_PARAMS` | 参数缺/格式错 | 看 message 里的字段名 |
| `UNSUPPORTED` | 方法名不存在 | 拼写；或插件版本旧 |
| `TIMEOUT` | 超时 | 是否有模态对话框 |
| `REVIT_API` | Revit 内部异常 | 看 message 原文 + plugin.log |
| `INTERNAL` | 未预期异常 | plugin.log 里的堆栈 |
