## 二、线程模型（最重要的一节）

Revit API **不是线程安全的**，只能在主（UI）线程调用。而 TCP 收包必然在后台线程。
处理不好就会出现两类经典故障：随机崩溃、Revit 界面假死。

```
TCP 线程                          Revit UI 线程
─────────                        ───────────────
收到 build_ir
   │
   ├─ 投递 Job 到队列
   ├─ ExternalEvent.Raise() ──────► Execute(UIApplication)
   └─ 阻塞等 ManualResetEventSlim          │
                                           ├─ 出队 Job
                                           ├─ 开事务 → 建构件 → 提交
                                           ▼
                                     Done.Set()
   ◄────────────────────────────────────┘
返回 JSON 结果
```

要点：

| 要点 | 说明 |
|---|---|
| `ExternalEvent.Create` 在 startup 创建一次 | 反复创建会泄漏 |
| 队列用 `ConcurrentQueue` | 多连接/并发请求安全 |
| 每次 `Raise()` 处理**整个队列** | 避免一次事件只处理一个请求的效率损失 |
| 超时保护（默认 10 分钟，build_ir 60 分钟） | Revit 弹出模态对话框时会卡住，超时给客户端明确错误而不是无限等 |
| UIApplication 从 `Execute(app)` 参数取 | `UIControlledApplication.Idling` 的 sender 不是 UIApplication（**这是常见错误**） |

## 三、事务策略

两种模式，按规模选：

| 模式 | 行为 | 何时用 |
|---|---|---|
| `single_transaction`（默认） | 全部构件一个事务；任一 `errors` 非空则**整体回滚** | 少量构件、要求"要么全有要么全无" |
| `per_element` | 每类构件一个事务，失败只影响该类 | 大规模、或想"先看到成功的部分" |

代码里统一用 `tx.GetStatus() == TransactionStatus.Started` 判断再 Commit/RollBack。
**这是必须的**：builder 内部出错时可能已经自行回滚，此时再 Commit 会抛
`The transaction has been rolled back or committed`，把真实错误掩盖掉。

## 四、Revit 2022 专有注意事项

### 4.1 单位

| 场景 | 做法 |
|---|---|
| API 内部单位 | **永远是英尺**。所有 IR 值经 `RevitUtils.MmToFeet()` |
| 界面显示单位 | `doc.GetUnits()` → `SetFormatOptions(SpecTypeId.Length, ...)` |
| **不要用** | `UnitType.UT_Length` / `DisplayUnitType` —— Revit 2022 起已废弃，会编译警告、未来版本移除 |

```csharp
// Revit 2022 正确写法
var units = doc.GetUnits();
units.SetFormatOptions(SpecTypeId.Length,
    new FormatOptions(UnitTypeId.Millimeters, 0.1) { SuppressTrailingZeros = true });
doc.SetUnits(units);
```

### 4.2 目标框架

Revit 2022 运行时是 **.NET Framework 4.8**。不能改成 `net6.0`/`net8.0`，否则插件加载失败。

```xml
<TargetFramework>net48</TargetFramework>
<PlatformTarget>x64</PlatformTarget>   <!-- Revit 只有 64 位 -->
<LangVersion>9.0</LangVersion>          <!-- 可用 record/模式匹配，但不会用到 .NET 6 API -->
```

### 4.3 API 引用两种方式

**方式 A：本机 Revit 安装目录（设计院离线环境推荐）**

```xml
<Reference Include="RevitAPI">
  <HintPath>C:\Program Files\Autodesk\Revit 2022\RevitAPI.dll</HintPath>
  <Private>False</Private>   <!-- 关键：不能复制到输出目录 -->
</Reference>
```

`Private=False` 必须加。复制 RevitAPI.dll 会导致运行时加载到两份不同版本，报
`Could not load file or assembly 'RevitAPI'`。

**方式 B：NuGet（CI / 无 Revit 的机器）**

```powershell
.\scripts\build-addin.ps1 -UseNuget
```

用 `Nice3point.Revit.Api.RevitAPI` / `Nice3point.Revit.Api.RevitAPIUI`，`2022.*` 版本。

### 4.4 序列化

Newtonsoft.Json **13.0.3**——与 Revit 2022 自带版本一致。
版本不一致会被 Revit 的绑定重定向搞成 `Could not load Newtonsoft.Json` 的经典错误。

### 4.5 部署路径

| 范围 | 路径 | 权限 |
|---|---|---|
| 单用户（推荐） | `%APPDATA%\Autodesk\Revit\Addins\2022\` | 无需管理员 |
| 全机器 | `C:\Program Files\Autodesk\Revit 2022\AddIns\` | 需管理员 |
| 仅本次 | 同单用户，删掉 .addin 即卸载 | — |

`.addin` 里 `<Assembly>revit-wy\RevitWy.Plugin.dll</Assembly>` 是相对 `.addin` 所在目录的相对路径，
所以 DLL 要放在 sub 目录里，`.addin` 放在上一层。

## 五、类型匹配：翻模成败的关键

翻模失败的原因排序（我实测）：

1. **类型不存在**（60%）
2. 几何不对（30%）
3. 族参数名不匹配（10%）

所以 `TypeResolver.cs` 是插件里最值得打磨的类。三级兜底：

```
ResolveWallType(厚度, 类型名提示)
  │
  ├─ 1) 名称精确匹配（含去重名后缀比较）
  ├─ 2) 厚度相近 ±20mm
  ├─ 3) 复制基准类型 → 改核心层厚度 → 改名
  └─ 4) 全失败 → 用默认类型 + 记录 warning（不中断）
```

**步骤 3 的细节**（容易写错的地方）：

```csharp
var cs = newType.GetCompoundStructure();
int idx = cs.GetFirstCoreLayerIndex();          // 必须是核心层，不是第 0 层
double delta = 目标厚度 - cs.GetLayerWidth(idx);
cs.SetLayerWidth(idx, cs.GetLayerWidth(idx) + delta);   // SetLayerWidth 是"设置"不是"增减"
newType.SetCompoundStructure(cs);
```

用 `SubTransaction` 包起来，复制失败只回滚这一小步，不影响主事务。

### 族参数名的兼容

国内族参数名五花八门，统一按候选列表试：

```csharp
TrySetParam(e, new[] { "b", "宽度", "Width" }, value);
TrySetParam(e, new[] { "h", "高度", "深度", "Depth" }, value);
```

### 门窗族匹配

优先用块名/提示词做族名包含匹配，再退到宽度匹配，最后取第一个可用的。
`ResolveOpeningSymbol(isDoor, widthMm, hint)`。**不要严格匹配**——严格匹配在实际图纸上命中率极低。

## 六、构件生成的 API 用法

### 墙

```csharp
var curve = Line.CreateBound(p1, p2);   // p1/p2 的 Z 用标高 elevation
var wall = Wall.Create(doc, curve, wallTypeId, levelId,
                       heightInFeet, offsetFeet, flip: false, structural: isStruct);
```

- 高度用**无约束高度**而非顶部约束：不依赖标高名是否正确，更稳
- `structural` 由 IR 的 `profile` 推导（结构图 → 结构墙）
- 之后调 `WallUtils.AllowWallJoinAtEnd` 允许接头，`doc.Regenerate()` 让接头生效

### 柱

```csharp
var inst = doc.Create.NewFamilyInstance(xyz, symbol, level, StructuralType.Column);
// 旋转
ElementTransformUtils.RotateInstance(inst, Line.CreateBound(xyz, xyz + XYZ.BasisZ), rad);
```

必须用带 `StructuralType` 的重载，否则会被当成建筑柱（类别错、明细表统计不到）。

### 梁

```csharp
var inst = doc.Create.NewFamilyInstance(line, symbol, level, StructuralType.Beam);
```

梁顶默认对齐标高，所以 Z 直接用 `level.Elevation`，不需要额外偏移。

### 门窗（最容易失败）

```csharp
var inst = doc.Create.NewFamilyInstance(xyz, symbol, hostWall, level,
                                        StructuralType.NonStructural);
```

宿主墙三级兜底（`OpeningBuilder.FindHost`）：

1. IR 里的 `host_wall_id` → 本次生成的墙字典
2. 就近搜索：点到墙中心线距离 ≤ (墙厚/2 + 150mm)
3. 文档内已有墙，400mm 内

**仍找不到就不插**。硬插会产生悬空构件，事后清理比不建更麻烦。

### 楼板

```csharp
var loop = CurveLoop.Create(curves);            // 必须闭合且不自交
var floor = Floor.Create(doc, new List<CurveLoop>{loop}, floorTypeId, levelId);
```

先把相邻重复点去掉（<1mm），否则 `Line.CreateBound` 会报 `Curve is too small`。

## 七、清理与可重复执行

每个生成的构件都写入标记：

```csharp
var p = e.get_Parameter(BuiltInParameter.ALL_MODEL_INSTANCE_COMMENTS);
p.Set("revit-wy:" + layerName + "|" + irId);
// 例：revit-wy:A-WALL-200|wall-afa579085d
```

- 「清理上次翻模」按前缀扫描删除，**只删带标记的，不动手工模型**
- 改图重跑的标准流程：清理 → 重跑，不会产生重复构件
- 标记里带图层名，出问题时能反查"这面墙来自哪张图的哪个图层"

### 排错决策树

```
Revit 里看不到 revit-wy 功能区？
  ├─ 检查 %APPDATA%\Autodesk\Revit\Addins\2022\RevitWy.Plugin.addin 是否存在
  ├─ 看 plugin.log 有无 "启动失败"
  ├─ DLL 是否被"锁定"（从网上下载的会，右键属性→解除锁定）
  └─ Newtonsoft.Json.dll 是否一起拷过去了

功能区在，但 doctor 说 connected=false？
  ├─ 点「连接状态」看是否"运行中"
  ├─ 端口被占用 → 改 config.json 的 Port，同步改 Python 侧
  └─ 点「重启服务」

写入模型报 NO_DOCUMENT？
  └─ Revit 没有打开项目文档（只有起始页不算）

写入报"无可用墙类型"？
  └─ 样板里没有基本墙类型 → 换建筑样板或先建一个墙类型
```
