# 项目使用说明：它有什么能力、怎么用

> 面向两类人：
> **① 现场工程师** —— 只想把一张图翻成模型，看第 1、2 节就够；
> **② 技术负责人 / 领导** —— 想知道它能干什么、边界在哪、值不值得推广，看第 3、4、6 节。

---

## 一、三十秒上手

### 1.1 最省事的用法：双击

仓库根目录有两个 `.bat`，双击就行：

| 文件 | 作用 | 什么时候用 |
|---|---|---|
| **`一键启动.bat`** | 自动装环境、编译插件、配 MCP、启动工作台 | 第一次用 / 换电脑 |
| **`一键诊断.bat`** | 生成 `诊断报告_*.txt` | 出问题要找人看时 |

`一键启动.bat` 做六件事，全程不需要敲命令：
1. 检测 Python（没有就提示去哪下）
2. 建 `.venv` 并装依赖（失败自动换清华源重试）
3. 编译并部署 Revit 插件（没装 Revit 的机器会跳过并说明）
4. 写入 Cursor / WorkBuddy 的 MCP 配置（**合并，不覆盖你已有的**）
5. 用样例图自检五阶段流水线
6. 启动工作台并自动打开浏览器

`一键诊断.bat` 会跑一份完整体检，最后给出**"你现在能用到哪一步"**的结论：

| 结论 | 含义 |
|---|---|
| **A. 全功能可用** | 流水线通 + Revit 2022 在，可以真正写入模型 |
| **B. 可用但写不进 Revit** | 清洗/对照/构件清单/可视化/导出全可用，只是不能落模型 |
| **C. 环境未跑通** | 按报告里的建议逐条处理 |

### 1.1b 没有 Revit 也能先看效果

这是最容易被误解的一点：**本项目九成的价值不需要 Revit**。

```powershell
revit-wy demo                    # 一条命令走完全流程（自动起一个假 Revit）
```

它做四件事：起假 Revit → 跑五阶段流水线 → 干跑+写入（写进假后端）→ 报减负账。
不生成真实几何，但你能立刻看到构件清单、确认单、差异、工时账长什么样。

想让假 Revit 常驻、给 MCP/工作台连：`revit-wy mock`（前台占一个端口，Ctrl+C 结束）。

> 装好 Revit 2022 后，同一套命令换成 `--send` 就是真写入。
> 差别只有"几何真的被建出来"这一层，其他环节完全一致。

### 1.2 命令行：一条命令翻一张图

```powershell
revit-wy dwg 图纸\F1.dwg
```

输出长这样（五阶段进度 + 结果 + 下一步）：

```
  F1.dwg  →  arch
  ✔ 转换 DWG→DXF      3.20s   accoreconsole 转换成功
  ✔ 图纸体检            0.07s
  ✔ 数模对照            0.04s
  ✔ 图纸清洗            0.06s   建模层 5 个 / 隔离层 2 个 / 忽略层 1 个
  ✔ 生成构件            0.05s   共 14 个构件

  构件台账：墙 5｜柱 0｜梁 0｜门 1｜窗 1｜板 0｜轴网 5｜标高 2
  减负估算：手工 0.22h → 净省 0.16h（74.2%）
  数模对照：C:\Users\你\.revit-wy\work\F1\review\mapping_review.md
  构件清单：C:\Users\你\.revit-wy\work\F1\F1.ir.json
   · 看效果：revit-wy panel 图纸\F1.dxf  → 浏览器打开 http://127.0.0.1:8770/
   · 落模型：revit-wy build 图纸\F1.dxf --dry-run 先干跑；确认后 --send 写入 Revit 2022
```

**注意它只到"构件台账"为止，没有动你的 Revit 模型。** 这是故意的。

### 1.3 三个必须理解的设计

| 设计 | 为什么 | 你会感受到什么 |
|---|---|---|
| **宁停不乱建** | 建筑改错的返工成本远高于画一遍 | 图层没归好类时它会停下来，列出是哪几个图层 |
| **写入要两次确认** | 防止 AI 或手滑直接改你的模型 | `--dry-run` 干跑看清单，`--send` 才真写 |
| **不猜图层归属** | 猜错一次，整层墙都错 | 给出置信度和依据，不确定就问你 |

## 二、完整流程

### 2.1 标准五步

```
① DWG ──转换──► DXF 2018         （accoreconsole / ODA / AutoCAD 手工另存）
② DXF ──体检──► 图层清单+单位     （发现单位错 1000 倍这类灾难的前置）
③ 体检 ──对照──► 数模对照确认单   （人看 md/csv，确认"这层是墙"）
④ 确认 ──清洗──► clean.dxf        （隔离非建模层、删垃圾、修单位）
⑤ 清洗 ──建IR──► model.ir.json    （墙柱梁门窗板轴网，全自动）
⑥ IR  ──写入──► Revit 2022        （干跑 → 确认 → 真写）
```

`revit-wy dwg` 一把跑完 ①–⑤。第 ⑥ 步永远手动，这是安全边界。

### 2.2 每一步都能单独跑（排错时用）

| 命令 | 干什么 | 典型用途 |
|---|---|---|
| `revit-wy doctor` | 环境自检（简版） | 装完先跑这个 |
| **`revit-wy diag`** | **完整体检 + 结论文本报告** | **出问题先跑这个，报告直接发人** |
| **`revit-wy demo`** | **无 Revit 演示全流程** | **第一次想看看它到底能干什么** |
| `revit-wy mock` | 起假 Revit（协议仿真） | 想用 MCP/工作台对着假后端练 |
| `revit-wy install-mcp` | 写 MCP 配置（合并） | 换客户端 / 重装后修配置 |
| `revit-wy dwg2dxf <目录>` | 批量 DWG→DXF | 一次转一整个专业 |
| `revit-wy scan a.dxf` | 图纸体检 | 看单位、图层、实体数 |
| `revit-wy review a.dxf -p arch` | 出数模对照单 | 给工程师确认 |
| `revit-wy confirm --set "A-WALL=wall"` | 回灌确认结果 | 命令行走得快 |
| `revit-wy build a.dxf --dry-run` | 干跑 | 看要建什么 |
| `revit-wy build a.dxf --send` | 真写入 | 落模型 |
| `revit-wy saving model.ir.json` | 算减负账 | 给领导看 |
| `revit-wy panel a.dxf` | 开工作台 | 可视化核对 |

### 2.3 三个专业怎么用

```powershell
revit-wy dwg 建筑.dwg -p arch       # 建筑：墙/门/窗/轴网
revit-wy dwg 结构.dwg -p struct     # 结构：柱/梁/板/轴网
revit-wy dwg 机电.dwg -p mep        # 机电：仅识别隔离（一期不做建模）
```

三类图放一起也行，`-p` 决定用哪套图层命名规范。

## 三、能力清单

### 3.1 能做什么（已验证）

| 能力 | 状态 | 验证方式 |
|---|---|---|
| DWG → DXF 批量转换 | ✅ | accoreconsole 并发，失败可诊断 |
| 图层识别（命名不规范也能认） | ✅ | 6 级匹配：精确/别名/正则/模糊/语义/兜底 |
| 数模对照确认单 | ✅ | 产出 md + csv + json + yaml 四件套 |
| 楼板、轴网、双线墙自动配对 | ✅ | 墙线吸附、中心线提取、轴号识别 |
| 门窗自动挂宿主墙 | ✅ | 就近墙距离 + 同层判断 |
| 单位自动归一（mm） | ✅ | $INSUNITS 识别，防 1000 倍错 |
| 数模差异比对（改图后增量） | ✅ | 按几何签名，**整体平移自动对齐** |
| 减负工时估算 | ✅ | 基线可改，单图/批量都行 |
| 全自动写入 Revit | ✅ | 干跑清单 + 双确认 |
| 浏览器可视化工作台 | ✅ | 5 页签，点构件联动 Revit 选中 |
| MCP 接入 Cursor / WorkBuddy | ✅ | 13 个工具 |
| Windows 一键启动 / 诊断 | ✅ | 双击 .bat |

### 3.2 做不到（一期不做）

| 不做 | 原因 |
|---|---|
| 直读 DWG 二进制 | ezdxf 只支持 DXF；本机有 AutoCAD 时自动转 |
| 出图（视图/标注/明细表） | 一期只建模，出图是独立的大工程 |
| 机电管线建模 | 二期；目前只做识别隔离，避免误建 |
| 弧形墙真实曲面 | 离散为 24 段（可配 segments 数） |
| 钢筋 | 二期 |
| 单张图多楼层自动拆分 | 需图框解析，二期 |
| 无 AutoCAD 且无 ODA 时读 DWG | 必须有转换器，这是物理限制 |

### 3.3 比"能做什么"更重要的是"什么时候会停下来问你"

这是工具可信度的关键。它会在以下情况**主动停下**并说明原因：

| 情况 | 它会怎么说 |
|---|---|
| 有图层归不了类 | `有 8 个图层未能自动归类，需人工确认` + 列出图层名 |
| 图纸单位可疑 | `图纸单位为 1000mm，已自动换算（R1 风险点）` |
| 清洗后没构件 | `清洗后没有提取到任何构件：检查图层是否被整体 isolate/ignore` |
| DWG 转不了 | 列出三条补救路径（关 AutoCAD / 绑定 XREF / 手工另存） |
| 安全闸未开 | `必须同时传 dry_run=false 且 confirm=true` |

## 四、可视化工作台

```powershell
revit-wy panel samples\arch_plan.dxf    # → http://127.0.0.1:8770/
```

| 页签 | 能干什么 |
|---|---|
| **图层** | 看每层归属 + 置信度 + 匹配依据，改下拉立即重算 |
| **构件** | 墙柱梁门窗逐条列，点一行 → 图上高亮 + Revit 里选中缩放 |
| **差异** | 和上次写入的模型比（按几何，不按 id），改图重跑前先看影响面 |
| **规则** | 层高/墙厚/门窗尺寸热改，秒级重算 |
| **导出** | md / csv / json / yaml |

为什么是浏览器而不是嵌在 Revit 里：详见 `docs/06`。一句话——WebView2 在 Revit 里有 4 条已知崩溃路径。

## 五、给工程师：它帮你省了什么

（数字来自 `revit-wy saving`，工时基准在 `config/effort_baseline.yaml` 可改）

以一层标准办公楼层为例：120 道墙、40 根柱、60 根梁、30 樘门、40 扇窗、12 块板。

| 环节 | 手工 | 用本工具 |
|---|---|---|
| 开图对位、建类型 | 5 分钟 | 自动 |
| 轴网 | 20×45s ≈ 15 分钟 | 自动 |
| 柱 | 40×40s ≈ 27 分钟 | 自动 |
| 墙 | 120×25s ≈ 50 分钟 | 自动 |
| 梁 | 60×35s ≈ 35 分钟 | 自动 |
| 门窗 | 70×90s ≈ 105 分钟 | 自动 |
| 板 | 12×15s ≈ 3 分钟 | 自动 |
| **小计** | **约 4.1 小时** | — |
| AI 处理 | — | 约 10 秒 |
| 人工复核（抽检 25% + 目视校核） | — | 约 40 分钟 |
| **净结果** | **4.1 小时** | **约 0.6 小时** |

**提效约 84%。** 这个数字我特意压过：
- 不假设"零复核"，25% 抽检 + 每张图 10 分钟目视校核都算进去了；
- 不算返工（返工省得更多，但不写进来更可信）；
- 小图（比如只有 3 道墙）首次使用是**负收益**（要调规则），工具会如实显示负数。

**对工程师真正重要的不是这 84%，而是**：省下来的是"对图、数墙、点选、改类型"这种不产生设计价值的动作。
设计判断还在人手里，这才是"减负"的正确含义。

## 六、常见问题

**Q：我的图是 DWG，没有 AutoCAD 能用吗？**
A：能，但要装免费的 ODA File Converter（`revit-wy dwg2dxf --oda`）。都没有的话让上游给 DXF 2018。

**Q：图层名很乱，比如"墙体 200""图层1|柱子"能认吗？**
A：能，`samples/messy_plan.dxf` 就是这个场景的回归测试。认不准会问你，确认一次记住永久。

**Q：我装的是 Revit 2024/2025，能用吗？**
A：能。项目支持 2022 及以上。2022–2024 与 2025+ 分属两条运行时线
（.NET 4.8 / .NET 8），插件要按版本分别编译，`scripts\build-addin.ps1 -Deploy`
会自动识别本机版本逐个编译部署。细节见 `docs/10`。

**Q：会不会把我的模型改坏？**
A：不会。写入必须两次确认（`--dry-run` 看清单 + `--send` 才写），且重复翻模靠 `Comments` 里的标记精确清理，不会误删手工建的构件。

**Q：改了图再翻一次，会不会重复建？**
A：不会。差异比对按几何签名（不是随机 id），并支持**整体平移自动对齐**——图纸挪了位置也能认出是同一批构件。

**Q：AI（Cursor/WorkBuddy）能自己按生成键吗？**
A：不能。工具层强制拦截，这是设计不是限制。详见 `docs/08`。

**Q：出了错怎么排查？**
A：双击 `一键诊断.bat`，把生成的 txt 发出来。里面有 Python/Revit/端口/MCP 配置/流水线自检/插件日志，
最后一段直接写"你现在能用到哪一步"和待办清单。

**Q：诊断脚本为什么不用纯 batch 写？**
A：因为踩过坑。batch 的 `>> file echo ...` 和 `if (...)` 括号块混用会被 cmd.exe 解析错位，
上一版就吐出过 `'EPORT" echo [X] 未部署插件' is not recognized` 这种假错误，把真问题盖住了。
现在 `.bat` 只负责找 Python，判断逻辑全在 `src/revit_wy/diagnose.py`，可测试、可读。
