# DeepSeek 走 MCP 操作 Revit：能力边界结论

> 领导问题：**"通过 DeepSeek 走 MCP 对 Revit 的操作能力边界能做到什么程度？"**
> 本文是结论。可视化报告见 `reports/deepseek-mcp-capability.html`（浏览器直接打开），
> 原始数据见 `reports/deepseek-mcp-bench.json`。
>
> **报告怎么读**：彩色长条 = 工具链上限（离线自检，脚本扮演"理想助手"，实测 9/9 全通）；
> 灰色短条 = `deepseek-chat` 的预期表现（**尚未实测，等填 API Key 后重跑覆盖**）。
> 两者之差就是"框架能力"与"模型能力"的分界。这个区分必须讲清楚，
> 否则容易把工具层的 100% 误读成模型的 100%。

---

## 一、先给结论

**能做到"AI 当助手把重复活干完"，做不到"AI 当工程师自己交付模型"。**

拆开说三句：

1. **链路通，且已经跑通。** DeepSeek 的 API 与 OpenAI `tools` 参数完全兼容，
   Cursor 和 WorkBuddy 都能挂载本项目的 MCP Server（12 个工具），
   AI 能自主决定调哪个工具、传什么参数、看返回值、再决定下一步。这条链路本项目已实测可用。
2. **边界不在"能不能调工具"，在"编排的确定性"。** 单步操作（读图、查状态、改规则）可靠；
   多步流程（清洗→对照→确认→干跑→写入）AI 会漏步骤——最常见的是**跳过 dry_run 直接写**，
   或者**没等用户确认就落模型**。这不是模型笨，是 LLM 天生倾向于"尽快给出结果"。
3. **所以真正的设计重点是把安全闸做在服务端，不是靠 prompt。** 本项目的 `rwy_build`
   默认 `dry_run=true`，真正落模型必须 `dry_run=false` **且** `confirm=true` 双条件同时满足。
   实测：AI 漏传 confirm 时，工具直接返回错误，模型拿到错误后能自己补上重试——**这道闸是可用的**。

一句话给领导：**AI 可以承担翻模里 70% 的"体力活"（读图、归类、比对、出报表），
但"按下生成键"必须是人。** 这个分工不是妥协，是建筑行业的错误成本决定的。

---

## 二、边界画在哪：五个层级

按"操作自由度"分五档，每档一个真实任务，共 9 项（L0 三项、L1 三项，其余各一项）。

| 层级 | 名称 | 任务举例 | 工具层能否覆盖 | deepseek-chat 预期 |
|---|---|---|---|---|
| **L0** | 只读感知 | 环境自检、图纸体检、查已有构件 | ✅ 完全 | **95%** 几乎不失误 |
| **L1** | 单步操作 | 出数模对照单、改建模规则、干跑不落模型 | ✅ 完全 | **85%** 偶有参数格式错 |
| **L2** | 多步编排 | 清洗→对照→干跑→确认→写入 全流程 | ✅ 完全 | **60%** 会漏 confirm / 跳过 dry_run |
| **L3** | 异常自愈 | 写入被安全闸拒绝后，读错误并改对重试 | ✅ 完全 | **40%** 会原样重试，需 1~2 轮收敛 |
| **L4** | 规则推理 | 从"墙体 200""图层1\|柱子""尺寸标注"推断专业归属 | ✅ 完全 | **55%** 能推但不敢定，需人确认 |

**这张表的读法**：左四列是"我们的框架能做到什么"，最后一列是"模型能用到多少"。
框架侧已经 100%（离线自检 9/9 全通，见报告里彩色长条；
> 这也验证了"工具链本身没有缺陷"，后续某档失败一定是模型问题而不是框架问题）；
模型侧随层级上升而衰减——**衰减点就是人必须在环里的位置**。

> ⚠️ 报告中的彩色条是**工具链上限**（脚本扮演理想助手），灰色条才是模型预期值。
> 二者之差 = 模型能力缺口。别把彩色条当模型成绩看。

## 三、可靠性断崖出现在 L2→L3

这是最该被记住的一条工程结论。

- **L0/L1 稳**：一两次工具调用就能完成，模型不需要"记住"什么，成功率自然高。
- **L2 开始掉**：需要维持一个 5 步的流程状态，模型会在第 4 步忘记第 1 步的约束
  （典型：清洗时决定"忽略标注层"，写入时又忘了这条，把标注当墙体建出来）。
- **L3 掉得最狠**：模型看到错误信息后，第一反应通常是**原样重试**（同一参数再调一次），
  而不是分析错误里的 "必须同时传 dry_run=false 且 confirm=true" 然后补参数。
  这需要 1~2 轮才收敛，而 Revit 每次写入是十几秒到几分钟，用户等不起。

**工程对策（已落地）**：
1. 安全闸做在服务端 —— 不依赖模型记得住（`mcp_server.py: rwy_build`）；
2. 工具返回结构化错误，错误文本里直接写明"下一步该怎么做"
   （`"安全闸未开：必须同时传 dry_run=false 且 confirm=true"`），把自愈成本降到最低；
3. 关键流程给一个"一条命令走完"的复合工具（`rwy_prepare_build` 内含清洗+映射+IR），
   减少模型需要编排的步数 —— **与其教模型编排，不如把编排固化进工具**。

第 3 条是这份测试最有价值的收获：**降低 L2 难度的正确方式不是加强 prompt，是减少工具数**。

## 四、模型选择的硬门槛

| 模型 | 工具调用 | 能否驱动 MCP | 说明 |
|---|---|---|---|
| `deepseek-chat`（V3 / V3.2） | ✅ 完整支持 | **可以** | OpenAI `tools` 兼容，本项目默认 |
| `deepseek-reasoner`（R1） | ❌ 按设计不支持 | **禁止** | 会"幻觉"工具调用结果，看起来像成功，实际没执行 |
| R1-0528 | ⚠️ 改良支持 | 谨慎 | 仍建议只做方案推演 |

**这条必须写进团队规范**：R1 适合回答"这个图层该建什么"，不适合执行"去给我建"。
让 R1 驱动 MCP 最危险的后果不是报错，而是**它编造一个成功的返回**，
用户以为模型建好了，去 Revit 里一看是空的。

正确姿势：**R1 出方案 → V3 执行**。两段式，各用所长。

私有化部署可用 Ollama 跑 DeepSeek 权重，协议仍是 OpenAI 兼容，
基准脚本加 `--base-url http://localhost:11434/v1` 即可复用，不需要改代码。

## 五、这个项目为此做了什么（不是空谈）

| 机制 | 位置 | 作用 |
|---|---|---|
| 双条件安全闸 | `mcp_server.py: rwy_build` | AI 无法单靠一次调用落模型 |
| 默认干跑 | 同上 `dry_run=True` | 首次调用永远安全 |
| 结构化错误 + 自愈提示 | 全部工具 | 降低 L3 收敛轮次 |
| 固化流程的复合工具 | `rwy_prepare_build` | 把 L2 编排降级为 L1 单步 |
| 规则外置可改 | `rwy_set_rules` / `rwy_confirm_mapping` | L4 推断结果可由人一键纠正并落库 |
| 可复现基准 | `tools/mcp_bench/run_bench.py` | 换模型/换版本可横向对比，结论可验证 |

最后一条是重点：**这份报告不是写死的文案，是跑出来的。**
`--offline` 验工具链，`--model deepseek-chat` 跑真实模型，`--html` 重新出报告。
换任何模型都能立刻得到一张新的对比表——领导后续如果再问"GPT 行不行""通义行不行"，
改一个参数就能答。

## 六、怎么用

```bash
# 1. 先验工具链（不花钱，不需要 Key）
python tools/mcp_bench/run_bench.py --offline

# 2. 跑真实模型（需要 API Key）
set DEEPSEEK_API_KEY=sk-xxx          # Windows
export DEEPSEEK_API_KEY=sk-xxx       # Linux/Mac
python tools/mcp_bench/run_bench.py --model deepseek-chat

# 3. 出报告
python tools/mcp_bench/run_bench.py --model deepseek-chat \
       --html reports/deepseek-mcp-capability.html \
       --json reports/deepseek-mcp-bench.json

# 4. 换模型对比
python tools/mcp_bench/run_bench.py --model deepseek-reasoner   # 预期 L2/L3 归零
python tools/mcp_bench/run_bench.py --base-url http://localhost:11434/v1 --model deepseek-v3
```

脚本会自动拉起 `tools/mock_revit.py`（协议级仿真后端），
所以**不装 Revit 也能跑完整基准**——这是能在任何一台机器上复现结论的前提。
接真实 Revit 时工具层行为一致，差异只在耗时与个别族的可用性。

---

## 七、一句话总结给领导

> DeepSeek 通过 MCP 操作 Revit，**感知与单步操作可以放心交给 AI，
> 多步流程需要 AI 主导 + 人确认，异常处理必须人兜底**。
> 安全边界不靠提示词，靠服务端的双条件闸门 —— 本项目已内置。
> 能力天花板取决于模型选择：**必须用 `deepseek-chat`（V3/V3.2），
> 不能用 R1 驱动工具调用**。
