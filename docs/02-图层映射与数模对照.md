# 图层映射与「数模对照」确认流程

> 对应需求：①DWG 图纸清洗与图层分层方案，并以数模对照形式交由用户选择确认
> ④图层命名不规范，需支持可定制的规范映射

---

## 一、为什么"自动识别"必须配"人工确认"

我做过统计：一套真实历史图纸里，通常有 3 类情况会击败任何"全自动"方案：

1. **同义不同名**：`A-WALL` / `墙体` / `Q-200` / `WAL` / `墙线` 都是墙
2. **同名不同义**：图层 `WALL` 里同时画了墙和窗台线
3. **语义缺失**：图层叫 `图层1`、`0`、`$0$A$C1234`

所以本方案的设计不是"猜得准"，而是**"猜 + 说清依据 + 一键确认 + 记住"**。

```
                  ┌──────────────┐
图纸图层 ────────► │ LayerMapper  │ ────► 每层一个 MatchResult
                  │ 6 层匹配      │        {component, confidence, matched_by, reason}
                  └──────────────┘
                            │
              ┌─────────────┼─────────────┐
              ▼             ▼             ▼
        ≥0.85 自动     0.55~0.85       <0.55 或未命中
        直接建模       建议确认 →      必确认 → 阻塞 --auto
                            │
                            ▼
                    ┌────────────────┐
                    │ 数模对照确认单   │  md / csv / json / yaml
                    └───────┬────────┘
                            │ 用户确认（3 种入口任选）
                            ▼
                    ┌────────────────┐
                    │ aliases.json   │  下次同名图层 confidence = 1.00
                    └────────────────┘
```

## 二、六层匹配规则详解

代码：`src/revit_wy/mapping.py`

### 2.1 归一化（先做，成本最低收益最高）

| 输入 | 归一化后 | 处理 |
|---|---|---|
| `Ａ-WALL`（全角） | `A-WALL` | NFKC 全角转半角 |
| `$0$A-WALL` | `A-WALL` | 去 AutoCAD 匿名块前缀 |
| `图层1|柱子`（Xref） | `柱子` | 去外部参照前缀 |
| ` 门 ` | `门` | 去首尾空白 |
| `a-wall` | `A-WALL` | 统一大写 |

### 2.2 匹配层级与置信度

| 层级 | 权重 | 示例 | 设计意图 |
|---|---|---|---|
| `alias` | **1.00** | 用户确认过的层 | 最高优先级，人的判断压过一切 |
| `exact` | 0.98 | `A-WALL` == `A-WALL` | 完全一致 |
| `glob` | 0.90 | `*WALL*` 匹配 `A-WALL-200` | 处理前后缀，最常用 |
| `contains` | 0.80 | `WALL` in `MY-WALL-LINE` | 更松的包含 |
| `regex` | 0.78 | `(?i)^a[_-]?wall` | 处理复杂命名规律 |
| `keyword` | 0.72 | 关键词 `剪力墙`、`KZ` | 中文/多义场景 |
| `fuzzy` | 0.60×相似度 | `WAL` ≈ `WALL`(0.86) | 拼写错误、缩写 |

> 多个规则都命中时取**最高分**；同一规则内按上述顺序取第一个命中。

### 2.3 阈值策略

| 区间 | 处置 | 理由 |
|---|---|---|
| ≥0.85 | `build` 自动建模 | 高置信度，人工复核成本高于纠错成本 |
| 0.55–0.85 | 标记"建议确认"，仍可建模但报告里醒目 | 大概率对，留一个提醒 |
| <0.55 或未命中 | `manual_review`，**阻塞 `--auto`** | 宁可停下问人，不可瞎建 |

阈值本身可配（`auto_accept` / `manual_review`），院里如果更保守可调到 0.95。

## 三、8 类语义分层

不是把图层"分到几个名字"，而是映射到 **BIM 构件语义**：

| component | Revit 类别 | 一期动作 | 说明 |
|---|---|---|---|
| `wall` | `OST_Walls` | 建模 | 双线配对求厚度 |
| `column` | `OST_StructuralColumns` | 建模 | 闭合轮廓求截面 |
| `beam` | `OST_StructuralFraming` | 建模 | 双线取宽 |
| `door` | `OST_Doors` | 建模 | 需宿主墙 |
| `window` | `OST_Windows` | 建模 | 需宿主墙 + 窗台高 |
| `slab` | `OST_Floors` | 建模 | 闭合轮廓 |
| `grid` | `OST_Grids` | 建模 | 长直线 + 轴号文字 |
| `annotation`/`hatch`/`furniture` | — | **隔离**（`_WY_` 前缀 + 冻结） | 保留可查，不建模 |
| `ignored` | — | **删除** | 图框、DEFPOINTS、视口 |

### 为什么隔离而不是删除

- 出问题时能对比"原图有这个标注，模型这里没构件"——查错快一个数量级
- 用户后期想出图时可以解冻复用
- 删除不可逆，图纸清洗这种事不该有不可逆操作

## 四、自定义映射（需求 4 的落地方式）

### 4.1 三种自定义粒度

| 粒度 | 做法 | 适用 |
|---|---|---|
| **加别名**（最轻） | 确认单上确认一次，进 `~/.revit-wy/aliases.json` | 个别图层不规范 |
| **改规则** | 复制 `config/layer_mapping/arch.yaml` 后修改，`--mapping` 指定 | 整院命名体系不同 |
| **新增专业** | 新建 `config/layer_mapping/myprofile.yaml` | 新增专业/新客户 |

### 4.2 规则写法示例

```yaml
profile: arch
auto_accept: 0.85
manual_review: 0.55
fallback_component: manual_review

rules:
  - component: wall
    revit_category: OST_Walls
    name_cn: 墙
    priority: 100            # 越大越先匹配
    exact: [WALL, A-WALL]
    glob: ["*WALL*", "*墙体*"]
    regex: ["(?i)^q[-_ ]?\\d+"]     # Q-200 这类
    keyword: [墙, 剪力墙]
    thickness_suffix: '(?i)(?:wall|墙|q)[-_ ]*(\d{2,3})\s*(?:mm)?$'
    pair:                            # 双线配对参数
      min_thickness_mm: 60
      max_thickness_mm: 500
      parallel_tol_deg: 2.0
      overlap_min_ratio: 0.35
```

**`thickness_suffix` 是个高价值字段**：图纸上墙常画单线但图层名带厚度（`A-WALL-200`、`Q-200`、`墙-240`），
有这个正则就能在双线配对失败时直接取到厚度，识别率能拉回 20–30 个百分点。

### 4.3 不同专业的默认线索对照

| | 建筑 | 结构 | 机电（一期隔离） |
|---|---|---|---|
| 墙 | `A-WALL*`、`墙*` | `S-WALL*`、`Q-*`、`剪力墙` | — |
| 柱 | `S-COLU*`、`柱*`、`KZ*` | `S-COL*`、`KZ*`、`GZ*` | — |
| 梁 | — | `S-BEAM*`、`KL*`、`LL*`、`梁*` | — |
| 门/窗 | `A-DOOR*`、`门*`、`M-*`、`C*` | — | — |
| 板 | `*FLOOR*`、`楼板*` | `S-SLAB*`、`板*` | — |
| 轴网 | `AXIS*`、`轴线*` | `S-GRID*` | — |
| 隔离 | `A-DIM`、`HATCH`、`FURN` | `平法标注`、`钢筋` | `DUCT`、`PIPE`、`TRAY` |

## 五、数模对照单长什么样

`revit-wy review F1.dxf -p arch` 生成 `mapping_review.md`，核心是这张表：

| # | 图层名 | 实体数 | 主要图元 | 识别为 | Revit 类别 | 置信度 | 依据 | 处置 |
|---:|---|---:|---|---|---|---:|---|---|
| 1 | `墙体 200` | 1284 | LINE×1284 | 墙 | Walls | ✅ 0.90 高 | glob·通配匹配 *墙体* | 建模 |
| 2 | `A-WIND` | 96 | INSERT×96 | 窗 | Windows | ✅ 0.98 高 | exact·精确匹配 | 建模 |
| 3 | `图层1` | 412 | LINE×412 | 未识别 | — | ❓ 0.00 低 | 未命中任何规则 | **待确认** |
| 4 | `A-FURN` | 88 | INSERT×88 | 家具 | — | ✅ 0.90 高 | glob | 隔离 |
| 5 | `图框` | 1 | LWPOLYLINE×1 | 图框 | — | ✅ 0.90 高 | glob | 忽略 |

**"依据"列是关键**：它告诉你为什么这么判，你不用信任我，可以自己核。

## 六、三种确认入口

### 6.1 对话确认（Cursor / WorkBuddy，最自然）

```
你：扫描 F1.dxf 生成数模对照
AI：（调 rwy_review_mapping）→ 5 个图层需要确认，主要是「图层1」「墙线2」...
你：图层1 是墙，墙线2 也是墙，图框2 忽略
AI：（调 rwy_confirm_mapping({"图层1":"wall","墙线2":"wall","图框2":"ignore"})）
    → 已确认 3 个，写入别名库
你：准备建模
AI：（调 rwy_prepare_build）→ 墙 128 面、柱 24 根...
```

### 6.2 改表确认（批量、离线）

```powershell
# 1. 用 Excel 打开 mapping_review.csv
# 2. 在 override_component 列填 wall / column / beam / door / window / slab / grid / isolate / ignore
# 3. 回灌
revit-wy confirm --review mapping_review.csv
```

### 6.3 命令行直给

```powershell
revit-wy confirm --set "图层1=wall" --set "图框2=ignore"
```

> 三种入口最终都写同一个 `aliases.json`，**互不冲突、可混用**。

## 七、确认结果的复用性

`aliases.json` 是**用户级、跨项目**的：

```json
{
  "图层1": "wall",
  "墙线 2": "wall",
  "图框2": "ignore",
  "A-WALL-200": "wall"
}
```

含义：这套设计院的出图习惯一旦校准，后续所有图纸直接用。这是本方案**越用越快**的根本原因——
第一次 20 分钟确认，第十次 0 秒。

## 八、自动化程度对照

| 场景 | 需要人工确认的图层数 | 单图耗时 |
|---|---|---|
| 院内标准化图纸 | 0 | 全自动 |
| 同一设计院第二批 | 0–2 | 秒级确认 |
| 新客户首批 | 5–15 | 5–20 分钟 |
| 测绘/扫描转的 DWG | 可能 >30 | 建议先人工整理图层 |

`--auto` 模式会在存在必确认项时**直接中止并列出清单**，这是刻意设计——宁可停下来问，不可瞎建。
