## 二、第一阶段：本轮补了什么

新增 8 条规则、健康分、三种报告格式、批量修正入口：

```bat
revit-wy audit model --html reports\体检.html   :: 只读巡检，出报告
revit-wy audit csv   --out reports              :: 导出 JSON + CSV 分派整改
revit-wy audit fix --ids 1001,1002 --param mark --value 待补 --apply
```

MCP 侧新增三个工具：`rwy_audit_model` / `rwy_fix_issues` / `rwy_export_audit`。
详见 `docs/11-模型体检与数据治理.md`。

**"零建模破坏"是怎么保证的**：

| 动作 | 是否可能改模型 |
|---|---|
| `audit model` / `audit csv` | 否，纯 `FilteredElementCollector` 读 |
| `audit fix`（不带 `--apply`） | 否，干跑只返回数量 |
| `audit fix --apply` | 只写 `mark` / `comments` / `description` 三个文本参数，且必须显式给 id |
| 删空视图、删无用类型、改几何、换类型 | **不在本阶段，代码里没有这个入口** |

**还没做的**：`AuditCommands.cs` 只做了 tree-sitter 语法检查，没在真机编译过。
第一次 `.\scripts\build-addin.ps1 -Deploy -RevitVersions 2024` 可能报重载签名不符，
改动量在个位数行。

## 三、第二阶段：为什么说"已具备"

这一阶段的核心是**两段式建模 + 图层规则外置**，这两点在第四阶段就做完了：

| 你的要求 | 对应实现 | 位置 |
|---|---|---|
| 锁定单专业 | 三个 profile：`arch`（建筑）、`struct`（结构）、`mep`（机电识别隔离） | `config/layer_mapping/*.yaml` |
| 固定图层规范 | 每个 profile 里把图层名 → 构件类别写死，支持别名 | 同上 |
| 标准 CAD → 初版 BIM | `prepare_build`（只出计划）→ 人工确认 → `build`（真建） | `cli.py` / `mcp_server.py` |
| 半自动（不失控） | 图层无法自动归类就停：`max_manual_review=0`，"宁停不乱建" | `dwg_pipeline.py` |
| 压缩 60%+ | 一层标准层：手工 4.14 h → **净省 3.47 h = 83.7%** | `docs/07` |
| 沉淀规则库 | 人工确认的别名写回 YAML，同院图纸第二次零确认 | `mapping.py` |

**一个必须一起说的诚实数字**：`samples/struct_plan.dxf` 跑出来是 **−77.2%**
（净亏）。原因是结构图图层少、构件规整，手工建模本来就快，
而工具需要人工复核图层映射。**减负效果依赖图纸复杂度，不是所有图都省。**

**这一阶段真正缺的只有一件事**：你院的真实图层名不在 `config/*.yaml` 里。
需要拿 1–2 张典型图跑一次 `revit-wy map`，把确认结果固化进去。半天到一天。

## 四、第三阶段：为什么说"未开始"

现在有的只是**构件计数**（`report.py` 里的墙/柱/梁/门窗条数），
这不是工程量清单——没有体积、面积、混凝土标号、钢筋量、模板面积。

要做这一阶段，需要三块目前完全空白的能力：

1. **企业族库对接**：从你们的标准族库读类型参数（不是从 DXF 猜）。
2. **Excel 驱动**：读一张参数表 → 批量生成标准单元（卫生间、楼梯、机房）。
3. **算量引擎**：按类型/材质汇总，输出符合你们院格式的清单。

这一阶段的难点不在技术，在**标准化**：族库命名、参数名、计量规则
三家院三套，没有一个能通用的默认值。所以建议先跑通 ① ② 再评估。

## 六、必须诚实说明的三点

1. **第一阶段未在真机验证**。规则、报告、mock 联调都实测过（109 个测试通过），
   但 C# 插件只做了语法检查。第一次编译可能需要调几个 API 重载。
2. **健康分是自定口径**，不是行业标准。它用来在同一批项目间比高低、
   或者看同一个项目整改前后的变化，不适合跨院横比。
3. **效率数字建立在"逐个核对"假设上**。真实项目里工程师是抽查的，
   所以 18.2 分钟这个数字代表"全覆盖核对需要多久"，不是"你每周浪费了多少时间"。
   把它当上限看，不要当承诺。
