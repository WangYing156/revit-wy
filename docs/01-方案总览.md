# AutoCAD → Revit 2022「一键翻模」方案

> 版本 v0.1.0 ｜ 目标环境：Windows 10/11 + AutoCAD 2020–2024 + Revit 2022 + Python 3.9+
> 配套代码：`src/revit_wy`（清洗/映射/IR/MCP）、`addin/`（Revit 插件）、`tools/mock_revit.py`（协议仿真）

---

## 一、推荐方案

### 1.1 结论先说

| 决策点 | 结论 | 一句话理由 |
|---|---|---|
| 整体架构 | **三段式**：MCP 客户端 → Python MCP Server → Revit Add-in（TCP NDJSON） | Revit 只能跑在 UI 线程，插件无法当 stdio 子进程，必须用外部代理进程转接 |
| DWG 读取 | **AutoCAD `accoreconsole` 批量转 DXF(R2018) → `ezdxf` 解析** | 无界面、单图 1–3 秒、可并行、官方支持；比 COM 自动化快 5–10 倍且不抢焦点 |
| 图纸理解 | **纯几何 + 规则引擎**，不用视觉大模型 | 施工图是矢量精确数据，几何算法确定、可复现、可单元测试；视觉模型会给“看起来像”的错误结果 |
| 图层匹配 | **六层递进匹配 + 别名学习**：exact → glob → contains → regex → keyword → fuzzy | 命名不规范的图纸靠单条规则一定漏；分层匹配 + 置信度 + 人工确认闭环才稳 |
| 中间表示 | **IR（JSON，mm 单位）** 把"理解"和"建模"彻底解耦 | 可单测、可 diff、可回放、可人工审图；Revit 端只消费 IR，不碰 DXF |
| Revit 生成 | **C# 插件 + ExternalEvent + 单事务（可切分元素事务）** | API 非线程安全，必须回 UI 线程；单事务保证"全成或全不成" |
| 类型/族兜底 | **三级兜底**：精确名 → 厚度相近(±20mm) → 复制基准类型改厚度 | 翻模失败 80% 不是几何错，是"类型不存在" |
| 门窗消歧 | 按**块名 > 图层名 > 默认**判定门窗 | 国内图纸门窗常在同一图层，只能靠块名分 |
| 重复翻模 | 每个构件写 `revit-wy:<层名>|<id>` 到 Comments，支持精确清理 | 改图重跑必须能清干净，否则模型里堆三份墙 |

### 1.2 为什么不选另外几条常见路线

| 备选路线 | 为什么不推荐 |
|---|---|
| **直接用视觉大模型读 DWG/PDF 出构件** | 尺寸与定位不准（图纸上是 3600 它会读成 3.6m 或 3600cm）；无法保证可复现；出的错还是"看起来合理"的错，比明显报错更难查 |
| **AutoCAD COM 自动化（win32com）** | 每图启动完整 AutoCAD 界面，慢且抢焦点，批量 500 张图不可行 |
| **在 Revit 里直接读 DWG 链接（Import/Link CAD）** | 只能看不能改，几何是"导入符号"不是构件；且 Revit 2022 对 DWG 的图层过滤能力弱 |
| **纯 Dynamo 脚本** | 几何处理能力弱（双线配对、断线合并很痛苦）；Dynamo 调试成本高；跨专业复用差 |
| **现成商业翻模软件** | 无法接入 Cursor/WorkBuddy 的 MCP 工作流；图层规则不可定制；黑盒出错无法定位 |
| **MCP Server 直接写在 Revit 插件里（stdio）** | 插件加载在 Revit.exe 内，做 stdio 会阻塞 UI 线程导致 Revit 假死。这是社区踩过的坑，必须外部进程转接 |

### 1.3 架构图

```
┌─────────────────┐   MCP / stdio    ┌──────────────────────┐   TCP NDJSON    ┌────────────────────┐
│ Cursor          │◄────────────────►│ Python MCP Server    │◄───────────────►│ Revit 2022 Add-in  │
│ WorkBuddy       │   (12 个工具)     │ revit_wy.mcp_server  │  127.0.0.1:48880│ RevitWy.Plugin.dll │
└─────────────────┘                  └──────────┬───────────┘                 └─────────┬──────────┘
                                                │                                        │
                                     ┌──────────▼───────────┐                 ┌──────────▼──────────┐
                                     │ 图纸处理链            │                 │ ExternalEvent       │
                                     │ ① accoreconsole      │                 │  ├ LevelBuilder     │
                                     │   DWG→DXF            │                 │  ├ GridBuilder      │
                                     │ ② ezdxf 清洗/隔离     │                 │  ├ ColumnBuilder    │
                                     │ ③ LayerMapper        │                 │  ├ WallBuilder      │
                                     │ ④ 双线配对/中心线     │                 │  ├ BeamBuilder      │
                                     │ ⑤ IR（JSON, mm）      │────────────────►│  ├ OpeningBuilder   │
                                     └──────────────────────┘   build_ir      │  └ SlabBuilder      │
                                                                               └─────────────────────┘
```

**为什么这个形状是对的**

1. **职责单一**：几何理解（Python，易迭代、可测试）与模型生成（C#，必须 .NET）彻底分开。
2. **可审计**：中间产物 `model.ir.json` 是人能读的，出了问题一眼看出是"图纸没读懂"还是"Revit 没建对"。
3. **可降级**：AI 不可用时，`revit-wy build --send` 一条命令照样跑完整流程。
4. **协议极简**：NDJSON（一行一条 JSON），`telnet` 都能调试，不引入 gRPC/WebSocket 依赖。

## 二、模块拆解

### 模块 1：图纸清洗与图层分层（对应需求 1）

**文件**：`src/revit_wy/dwg.py`、`config/layer_mapping/*.yaml`

清洗做 5 件事，每一步都保留可追溯性：

| 步骤 | 动作 | 设计考虑 |
|---|---|---|
| 1 | 单位归一 | 读 `$INSUNITS`，1/4/5/6 全换算到 mm；无单位时按 mm 处理并**警示图幅异常**（>200m 提示疑似单位错） |
| 2 | 图层归类 | 每层判为 `build`（建模）/`isolate`（隔离）/`ignore`（删除）/`manual_review`（待确认） |
| 3 | 隔离 | 不改名不删除，而是**加 `_WY_` 前缀并冻结**——标注、填充、家具留着，方便对照检查，但不会被误建模 |
| 4 | 删除 | 只删确信无用的：图框、`DEFPOINTS`、视口 |
| 5 | 去噪 | 删零长度线、空文字；可选炸块（默认关闭，炸块会丢门窗属性） |

**图层分层方案（建筑/结构/机电三套，均可在 `config/layer_mapping/` 复制改名后自定义）**

分层不是"分到几个图层"，而是**分到 8 个语义类别**：

| 语义类别 | 建筑默认图层线索 | 结构默认图层线索 | 机电 |
|---|---|---|---|
| 墙 | `A-WALL`、`*WALL*`、`墙` | `S-WALL`、`剪力墙`、`Q-*` | — |
| 柱 | `S-COLU`、`柱`、`KZ*` | `S-COL*`、`KZ*`、`GZ*` | — |
| 梁 | — | `S-BEAM`、`KL*`、`LL*` | — |
| 门 | `A-DOOR`、`门`、`M-*` | — | — |
| 窗 | `A-WIND`、`窗`、`C*` | — | — |
| 楼板 | `*FLOOR*`、`楼板` | `S-SLAB`、`板` | — |
| 轴网 | `AXIS`、`轴线`、`GRID` | `S-GRID`、`轴线` | — |
| 隔离/忽略 | `DIM`、`HATCH`、`FURN`、`图框` | `平法标注`、`钢筋` | 风管/水管/桥架（一期隔离） |

**映射引擎如何接住"命名不规范"**（`mapping.py`）

- **归一化**：全角转半角（`ＷＡＬＬ`→`WALL`）、去 `$0$` 前缀、去 Xref 前缀（`图层1|柱子`→`柱子`）、统一大写。
- **六层匹配**，命中即记分：精确 0.98 / 通配 0.90 / 包含 0.80 / 正则 0.78 / 关键词 0.72 / 模糊 0.60×相似度。
- **别名学习**：你在确认单上认可一次，就写进 `~/.revit-wy/aliases.json`，下次同名图层直接 1.00 命中。**这套系统用得越久越准**。
- **置信度分流**：≥0.85 自动通过；0.55–0.85 标记"建议确认"；<0.55 进入必确认清单。`--auto` 模式下只要有一个必确认项就中止，绝不瞎猜。

### 模块 2：数模对照（对应需求 1 的"交由用户选择确认"）

**文件**：`src/revit_wy/report.py`

一次生成 4 份文件，分别服务 4 类读者：

| 文件 | 读者 | 用途 |
|---|---|---|
| `mapping_review.md` | 设计师 / 复核人 | 图纸体检 + 逐图层打分表 + 待确认清单 + 规则摘要 + 确认方式 |
| `mapping_review.csv` | 建模组 | 在 Excel 里批量填 `override_component` 列 |
| `mapping_review.json` | 程序 / CI | 结构化结果，可做回归比对 |
| `mapping_confirmed.yaml` | 机器 | 确认结果固化，二次运行免问 |

**三种确认入口**（都能落到同一份别名库）：

1. **对话确认**（Cursor/WorkBuddy 最自然）：
   > 「把『墙体-240』设为 wall，『图框2』忽略，其余保持」
   → AI 调 `rwy_confirm_mapping({"墙体-240":"wall","图框2":"ignore"})`
2. **改表确认**：Excel 填 CSV → `revit-wy confirm --review mapping_review.csv`
3. **全自动**：待确认项为 0 时 `--auto` 直接跑

> 关键设计：**确认动作写的是"别名"而不是"一次性覆盖"**。同一个设计院出图习惯固定，确认一次，后面 100 张图直接过。

### 模块 3：BIM 建模规则（对应需求 2）

**文件**：`config/bim_rules/default.yaml`

内置默认值全部可覆盖，三级优先级：**内置默认 < 用户覆盖(`~/.revit-wy/rules/default.yaml`) < 本次调用参数**。

| 规则组 | 关键默认值 | 可调项 |
|---|---|---|
| 单位 | mm / 自动换算 | `units.conversion` |
| 标高 | 层高 3000，命名 `{story}层`，自动生成 2 层 | `story_height_mm`、`name_pattern` |
| 墙 | 类型名 `常规 - {thickness}mm`，厚对齐 10mm，默认 200 | `type_name_template`、`thickness_round_mm`、`fallback_thickness_mm` |
| 柱 | 类型名 `{width}x{height}mm`，参数映射 b/h | `param_map` |
| 梁 | 默认 200×500，宽度取双线间距 | `default_b/h`、`b_from` |
| 门 | 900×2100，族兜底 `单扇 - 与墙齐` | `family_strategy`、`default_width_mm` |
| 窗 | 1500×1500，窗台 900 | `sill_height_mm` |
| 板 | 120 厚 | `default_thickness_mm` |
| 事务 | 单事务（失败全回滚） | `transaction_mode: per_element_commit` |

**给用户的三个选择档**（建议现场按需选一）：

| 档位 | 做法 | 适用 |
|---|---|---|
| A 保守 | 全部用内置默认，只在报错时调 | 第一次试跑、样本量小 |
| B 标准化 | 把院里的墙类型/门窗族命名先改到与模板一致，规则零配置 | 有企业样板、长期用 |
| C 全自定义 | 在 `~/.revit-wy/rules/default.yaml` 里写自己的一套 | 多专业、多项目并行 |

### 模块 4：Revit 2022 适配（对应需求 3）

**文件**：`addin/RevitWy.Plugin/`

| 关注点 | 实现 |
|---|---|
| 目标框架 | `net48`（Revit 2022 运行时是 .NET Framework 4.8，**不能用 .NET 6**） |
| API 引用 | 双路：本机 `Revit 2022\RevitAPI.dll`（离线推荐）或 NuGet `Nice3point.Revit.Api.*`（CI 用） |
| 单位 | IR 全 mm；`RevitUtils.MmToFeet` 统一转换（Revit 内部永远英尺） |
| 单位显示 | `SpecTypeId.Length` + `UnitTypeId.Millimeters`（`UnitType.UT_Length` 在 2022 已废弃） |
| 线程 | `ExternalEvent` 把请求排回 UI 线程，网络线程绝不碰 API |
| 事务 | 默认单事务；`per_element` 模式逐类提交 |
| 序列化 | Newtonsoft.Json 13.0.3（与 Revit 2022 自带版本一致，避免程序集冲突） |
| 部署 | `%APPDATA%\Autodesk\Revit\Addins\2022\`，无需管理员 |
| 排错入口 | 功能区「连接状态」「重启服务」「打开日志」三个按钮 |

**MCP 客户端适配**

Cursor 与 WorkBuddy 都支持 stdio 型 MCP，配置几乎一样，只有 Schema 细节不同：

| | Cursor | WorkBuddy |
|---|---|---|
| 配置位置 | `.cursor/mcp.json`（项目）或 `~/.cursor/mcp.json` | `%USERPROFILE%\.workbuddy\mcp.json` |
| 关键字段 | `command` / `args` / `env` | 多一个 `"type":"stdio"` |
| 额外动作 | 无 | **必须在连接器面板点 Trust**，否则工具禁用 |
| 配置样例 | `clients/cursor_mcp.json` | `clients/workbuddy_mcp.json` |

> 常见坑：WorkBuddy 的 `~/.workbuddy/.mcp.json`（带点的）是自动生成的，**改了会被覆盖**，必须改 `mcp.json`。
> Windows 下 `command` 必须写 `python.exe` 的**绝对路径**，因为客户端不继承你的 PATH。

**16 个 MCP 工具**（含模型体检三个：`rwy_audit_model` / `rwy_fix_issues` / `rwy_export_audit`）

| 工具 | 作用 |
|---|---|
| `rwy_doctor` | 自检：Python/ezdxf/配置/Revit 连通性 |
| `rwy_scan_drawing` | 图纸体检：单位、图幅、图层、图块、异常提示 |
| `rwy_review_mapping` | 生成数模对照单（需求 1） |
| `rwy_confirm_mapping` | 确认/修正映射，写入别名库 |
| `rwy_get_rules` / `rwy_set_rules` / `rwy_save_rules` | 建模规则读/改/存（需求 2） |
| `rwy_prepare_build` | 构建 IR + 质量指标，不写模型 |
| `rwy_build` | 写入 Revit（**默认 dry_run，需显式 double-confirm**） |
| `rwy_status` | 查 Revit 侧文档、标高层、构件数 |
| `rwy_dwg2dxf` | 批量 DWG→DXF |
| `rwy_diff` | IR 增量对比 |
| `rwy_audit_model` | ★模型体检：无用/空/未放置视图、缺参数、族命名、未使用类型（只读） |
| `rwy_fix_issues` | ★批量改白名单参数（mark/comments/description），默认干跑 |
| `rwy_export_audit` | ★导出巡检 JSON + CSV |

### 模块 5：构件全自动生成（对应需求 5）

生成顺序有硬性依赖，**不能乱**：

```
标高 → 轴网 → 柱 → 墙 → 梁 → 门窗 → 楼板
                    └─ 门窗必须 ensuite 墙（要 host）
       └─ 墙需要标高做基准/顶部约束
```

| 构件 | 识别方法 | 生成方法 | 失败兜底 |
|---|---|---|---|
| **墙** | 平行双线配对：角度差 ≤2° + 投影重叠 ≥35% + 间距 60–500mm → 中心线 + 厚度；单线图用图层厚度后缀（`A-WALL-200`） | `Wall.Create`，结构图出结构墙 | 厚度按 10mm 归整；类型三级兜底 |
| **柱** | 闭合多段线最小外接矩形 → b/h + 旋转角；圆 → 直径 | `NewFamilyInstance` + `StructuralType.Column`，按旋转角旋转 | 无柱族则跳过并提示载入 |
| **梁** | 双线配对取宽度；单线取默认宽 | `NewFamilyInstance(line, ...)`，梁顶随标高 | 默认 200×500 |
| **门/窗** | 图块插入点 + 块名/属性里的宽高；**块名判门窗** | 先定位宿主墙再插入 | 宿主墙三级兜底：IR id → 就近 150mm → 文档内 400mm；仍失败**不硬插** |
| **板** | 闭合多段线，面积 ≥10000mm² | `Floor.Create(CurveLoop)` | 去重相邻点，退化轮廓跳过 |
| **轴网** | 水平/垂直长线聚类 + 最近文字命名；**轴号黑名单**排除 `KZ1/KL2/G1` 这类构件编号 | `Grid.Create` | 重名自动加后缀 |

**几何算法要点**（`geometry.py`）

- **断线合并**：图纸上一条墙常断成多段，先按角度分桶再合并共线且间隙 ≤250mm 的段。
- **双线配对评分**：重叠长度优先，其次厚度接近常用值（100/120/150/180/200/240/250/300/370），避免把 200 厚的墙配成 800。
- **端点吸附**：200–300mm 容差内把墙端点吸到同一坐标，减少 Revit 里的缝隙。
- **去重**：起终点互换视为同一条墙。

## 三、关键约束与风险

### 3.1 硬约束（改变不了，只能设计绕开）

| 约束 | 影响 | 应对 |
|---|---|---|
| **ezdxf 不能读 DWG** | 必须一次格式转换 | 用 accoreconsole / ODA；或让上游交 DXF |
| **Revit API 非线程安全** | 网络线程直接调用会崩 | ExternalEvent 排队（已实现） |
| **Revit API 单位是英尺** | 直接传 mm 会得到 1/304.8 尺寸 | 所有入口经 `MmToFeet` |
| **族类型必须已存在或可复制** | 缺族就建不出构件 | 三级兜底 + 明确的"缺什么族"提示 |
| **Revit 2022 = .NET Framework 4.8** | 不能用 .NET 6/8 的新语法特性 | 目标框架锁定 net48，`LangVersion 9.0` |
| **门窗必须有宿主墙** | 无墙则无法插门窗 | 三级兜底；仍失败则跳过并报错，不留悬空构件 |

### 3.2 风险登记表

| # | 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|---|
| R1 | 图纸不是 1:1 或单位标错（画的是 m 但头写 mm） | 中 | **构件尺寸差 1000 倍** | 图幅 >200m 或最长墙 <50mm 时警示；`units.conversion` 可强制指定 |
| R2 | 墙用单线/多线/填充表达 | 中高 | 墙识别率骤降 | 图层厚度后缀兜底；单线模式降 confidence 到 0.35–0.6，在确认单里显式标出 |
| R3 | 门窗画在墙图层 / 门窗块没有属性 | 高 | 门窗丢失或尺寸错 | 块名判门窗；无属性时用规则默认尺寸并标注"尺寸来自默认值" |
| R4 | 图纸里 xref 未绑定 | 中 | 构件缺失 | 扫描时统计 `INSERT`，未绑定 xref 在报告里告警（一期不做自动绑定） |
| R5 | 同一张图含多层平面（拼图） | 中 | 全部堆到同一标高 | 一期：按图幅 `--base-level` 手动指定，逐图跑；二期：按图框自动切分 |
| R6 | 项目样板缺族（无柱/梁/门窗族） | 中 | 该专业全部跳过 | 干跑阶段就检测并明确报出"缺哪些族" |
| R7 | 工作共享模型 | 低中 | 构件被他人同步覆盖 | 检测 `IsWorkshared` 并告警；建议在本地副本上翻 |
| R8 | 大规模（>5000 构件）单事务卡死 Revit | 中 | Revit 无响应/用户以为崩了 | 提供 `per_element` 模式；建议按楼层分批 |
| R9 | 柱/梁截面参数名不统一（b/h/宽度/深度） | 高 | 截面尺寸不对 | `TrySetParam` 按中英文候选名列表逐个试 |
| R10 | 轴号与构件编号混淆（`KZ1` 被当轴号） | 中 | 轴网命名乱 | 轴号白名单 + 构件编号黑名单（已实现） |
| R11 | 弧墙/斜梁 | 中 | 几何失真 | 弧离散为 24 段线段（可配）；一期不做真实弧形墙 |
| R12 | 用户误让 AI 直接写入 | 低 | 模型被搞乱 | `rwy_build` 默认 dry_run，落模型必须 `dry_run=false` **且** `confirm=true` |

### 3.3 一期明确不做（避免范围蔓延）

- **出图**：不生成视图、标注、明细表、图框（你已确认一期只建模）。
- **钢筋**：不做配筋，平法标注层只隔离不解析。
- **机电建模**：只做图层识别与隔离，为二期留接口（把 `action: isolate` 改为 `build` 并补规则即可）。
- **弧形墙/异形柱/斜梁**：离散近似，不做真曲面。
- **多楼层自动分层**：需要图框/标高文字解析，二期做。

## 四、执行步骤

### 4.0 工期与人力估算

| 阶段 | 内容 | 人日 | 谁 |

| P4 | 批量跑 + 缺陷修复 | 2–3 | 你 + 我 |
| **合计** | | **5–7 人日** | |

> 一期（建筑+结构、只建模）的实际落地成本主要不在代码（已完成），而在**规则调优**——这依赖你手里的真实图纸。

### 4.1 第 0 步：环境搭建（双击即可，约 3 分钟）

```powershell
cd D:\revit-wy
.\一键启动.bat        # 自动：Python → 依赖 → 插件编译部署 → MCP 配置 → 自检 → 开工作台
.\一键诊断.bat        # 出问题时双击，生成 诊断报告_*.txt
```

脚本化安装（等价于双击，适合批量部署）：

```powershell
.\scripts\install.ps1

# 2) 重启 Revit 2022，功能区应出现 "revit-wy" → 点「连接状态」
#    看到 "运行中 / 127.0.0.1:48880" 即可

# 3) 自检
.venv\Scripts\python -m revit_wy.cli doctor
# 期望：revit_bridge.connected = true, revit_version = 2022
```

**验收**：`doctor` 里 `connected: true`，且返回的 `document` 是你打开的样板。

### 4.2 第 1 步：一条命令跑完前五阶段

```powershell
# ★ DWG 直接进：转换 → 体检 → 数模对照 → 清洗 → 生成构件
.venv\Scripts\revit-wy dwg D:\drawings\arch\F1.dwg -p arch

# 只看减负账
.venv\Scripts\revit-wy saving D:\drawings\arch\F1\F1.ir.json --md 减负报告.md
```

失败会立刻停下并说明卡在哪一阶段、下一步怎么办。逐阶段调试仍可用：

```powershell
# DWG 批量转 DXF（也可在 AutoCAD 里手工另存为 2018 DXF）
.venv\Scripts\revit-wy dwg2dxf D:\drawings\arch --workers 4

# 图纸体检
.venv\Scripts\revit-wy scan D:\drawings\arch\F1.dxf
```

**看三个数**：单位是不是 4（mm）、图幅是不是合理（住宅楼层约 30–80m）、图层数是否正常（通常 30–200）。

### 4.3 第 2 步：数模对照与确认（关键环节）

```powershell
.venv\Scripts\revit-wy review D:\drawings\arch\F1.dxf -p arch
# 产物在 D:\drawings\arch\F1\review\
```

同样的事在 Cursor 里更顺：

> 「扫描 F1.dxf，生成数模对照单」
> → AI 调 `rwy_review_mapping`
> → 返回 `need_review` 列表 → 你逐条看着报告确认
> → 「把『墙体-240』设为 wall，『窗台线』设为 ignore」
> → AI 调 `rwy_confirm_mapping`

**验收标准**：

- 待确认图层数 = 0
- 报告里"建模"类的实体数占比 >60%
- 墙的置信度 ≥0.85 的层覆盖了绝大多数墙线

### 4.4 第 3 步：干跑（不写模型）

```powershell
.venv\Scripts\revit-wy build D:\drawings\arch\F1.dxf -p arch --dry-run
```

看 `quality` 指标：

| 指标 | 健康值 | 不健康时怎么办 |
|---|---|---|
| `walls_from_pairing` 占比 | >70% | 偏低说明墙不是双线画法 → 检查图层名是否带厚度后缀 |
| `unpaired_lines` | <30% of wall lines | 偏高 → 调 `pair.max_thickness_mm` 或改 `--profile` |
| `hosted_openings / 总门窗` | >90% | 偏低 → 门窗离墙太远，或墙没识别出来 |
| `grids_named` | 大部分有真实轴号 | 偏少 → 轴号文字可能不在 `AXIS` 层 |

### 4.5 第 4 步：写入模型

```powershell
# 建议：先在空白样板 + 另存的新项目上试
.venv\Scripts\revit-wy build D:\drawings\arch\F1.dxf -p arch --send
```

或在 Cursor 里：

> 「确认无误，写入 Revit」
> → AI 调 `rwy_build(dry_run=false, confirm=true)`

**看返回的 `errors` 与 `warnings`**，重点关注：

- `找不到宿主墙` → 门窗与墙的几何没对齐
- `无可用墙类型` → 样板缺墙类型
- `柱已跳过。请先载入...` → 缺族

### 4.6 第 5 步：结构与迭代

```powershell
# 结构图同流程，只是换 profile
.venv\Scripts\revit-wy review D:\drawings\struct\S1.dxf -p struct
.venv\Scripts\revit-wy build  D:\drawings\struct\S1.dxf -p struct --dry-run
.venv\Scripts\revit-wy build  D:\drawings\struct\S1.dxf -p struct --send
```

**改图重跑的正确姿势**：

1. Revit 里点「清理上次翻模」（或 `delete_tagged` 协议方法）——只删带 `revit-wy` 标记的构件
2. 重新跑 `build --send`
3. 或者用 `rwy_diff` 比对两次 IR，只重建变更部分

### 4.7 验收标准（一期）

| 项 | 目标 |
|---|---|
| 图层映射准确率 | ≥95%（含人工确认后） |
| 墙识别率（双线图） | ≥90% |
| 门窗宿主成功率 | ≥90% |
| 构件尺寸误差 | 0（来自几何，不应有近似误差） |
| 一张标准层建筑平面（约 400 构件）全流程耗时 | ≤3 分钟 |
| 重复翻模不产生重复构件 | 是（靠 tag + delete_tagged） |

### 5.1 第 4 点里没提但该做的事（已做）

| 问题 | 原来 | 现在 |
|---|---|---|
| **重复翻模会叠加两份构件** | `rwy_build` 的 `would_delete` 写死 0，对用户撒谎 | 干跑真实报 `existing_tagged`；写入支持 `replace_existing` / `--replace`，只删带 `revit-wy` 标记的构件 |

| **静默降级** | 工时基线键名不匹配（`walls` vs `wall`）时默默用默认值 | 加 `_base_key` 归一 + 测试锁定 |
| **数字太漂亮** | 只算抽检，漏目视校核 | 复核含 25% 抽检 + 每图 10 分钟目视校核，提效率压到可信区间 |
