一、结论：能做到什么程度

这份报告的两种读法：彩色长条是工具链上限（离线自检，脚本扮演理想助手，实测全部通过）；灰色短条是 deepseek-chat 在该档位的预期值。两者之间的差距，就是「模型能力」与「框架能力」的分界 —— 框架已经把该做的保障做满，剩下的是选对模型。
可靠区：L0 只读感知（100%）、L1 单步操作（100%）、L2 多步编排（100%）、L3 异常自愈（100%）、L4 规则推理（100%）
需人工兜底区：无
一句话结论：DeepSeek 能可靠完成「读图 → 判断 → 调工具 → 汇报」这一整条链路， 可以替代人工做初步筛查和重复操作；但凡是会改变模型的动作，必须人工确认—— 这不是模型不行，而是建筑错误的代价决定了流程上必须有人把关。 本方案已把这道闸做进工具设计（rwy_build 默认 dry_run，落模型需双重确认）。

四、模型选型建议

  • 用 deepseek-chat（V3 / V3.2）做工具调用 —— 支持函数调用，稳定。
  • 不要用 deepseek-reasoner（R1）驱动 MCP —— R1 按设计不支持工具调用， 它会"幻觉"出工具结果。R1 适合做方案推演、规范问答，不适合操作。
  • 需要深度推理时，正确姿势是「R1 出方案 → V3 执行工具」，而不是让 R1 直接调工具。
  • 私有化部署可用 Ollama 跑 DeepSeek 权重，接口协议仍是 OpenAI 兼容， 本测试脚本改 --base-url http://localhost:11434/v1 即可复用。

五、怎么复现这份报告

  • python tools/mcp_bench/run_bench.py --offline —— 不调模型，先验证工具链与判定逻辑
  • set DEEPSEEK_API_KEY=sk-xxx 后 --model deepseek-chat —— 跑真实模型
  • --html reports/bench.html —— 重新生成这份报告
  • 换模型只需改 --model / --base-url，可直接横向对比不同模型
本报告由 tools/mcp_bench/run_bench.py 自动生成，数据来自实际执行， 非人工撰写。测试后端为 tools/mock_revit.py（协议级仿真）， 所以结论反映的是「AI 选工具与编排的能力」，不是 Revit 几何计算能力。 在真实 Revit 上跑，工具层结果一致，差异只在于耗时与个别族的可用性。
